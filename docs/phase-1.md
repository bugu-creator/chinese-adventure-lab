# Phase 1 · Homepage Foundation

## 实现

暖色文化冒险首页、原创 SVG 熊猫与文化景观、课程目录、四个游戏直达入口、身份导航、宠物与地图概念预览、教师课堂工具入口和建设中对话框。CSS 使用统一颜色、圆角、阴影变量，布局覆盖桌面、平板和手机断点，支持触控、键盘焦点、跳过导航和减少动态效果偏好。

原 index.html 完整保留为 learn.html；仅增加返回首页及白名单校验的课程/关卡深链接。多人游戏只增加返回首页，并修复请求对象中 session room 覆盖用户输入 room、导致加入失败的问题。服务端多人状态与游戏规则保持原实现，仅增加显式静态文件路径及 MIME 类型。

## 验证

`npm test`：5 项测试通过，覆盖页面与资源 HTTP 响应、MIME、首页链接锚点、内联脚本编译、课程入口存在、浏览器加入请求参数、多人 SSE、秘密词隔离、主持人/画画者权限、画板同步、答题计分、重复提交以及第二轮中文输入模式。

`git diff --check`：通过。

当前环境声明 managed Sites 模式，但未提供 cua_repl.js 共享浏览器控制工具。依照该模式要求未启动预览浏览器，因此尚未进行真实浏览器、iPad、朗读和 Apple Pencil 的视觉/交互验证；上述服务端和源码检查不等于浏览器验收。建议 PR 合并前在桌面及 iPad 检查布局、对话框、朗读、配对与实际多设备游戏。

## 部署范围与风险

保留 GitHub + Render 架构，不创建另一份托管站点。开发分支和 PR 不改变线上页面。合并 main 可能触发现有 Render 自动部署，并使正在进行的内存游戏房间因重启丢失；建议在无课堂游戏时发布。此阶段没有引入数据库或认证，教师入口不提供身份安全保障。

## Phase 2 建议

从原学习页提取 l1 原创课包为结构化数据，定义词汇、拼音、句型与问题 schema，建立课程页面模板，再逐步让单机和多人游戏共享词库。迁移时保留现有 API 和示例课程行为，并加入课包数据一致性检查。跨设备进度与长期宠物数据留待身份和持久化设计后实现。
